# Other Q&A

This document contains various Q&A about the codebase architecture and implementation details.

## Q: In Java, gRPC requires channel and stub. Where are they in this project? What kind of stub is it? Blocked or Async?

### Answer: No gRPC - This Project Uses REST HTTP + WebSocket

**Important:** This SDK does **NOT** use gRPC. It uses a custom REST HTTP API architecture with Protocol Buffers for message serialization only.

### The Equivalents:

#### 1. **Channel** → HTTP Client
**Location:** `pkg/network/http_client.go:15`

```go
var apiClient = &http.Client{Timeout: time.Second * 10}
```

This global HTTP client is reused for all API calls (like a gRPC channel).

#### 2. **Stub** → Generic API Type System
**Location:** `pkg/api/api.go:36-126`

Instead of generated gRPC stubs, this project uses a generic `Api[Req, Resp]` pattern:

```go
// Stub definitions
GetUsersInfo = newApi[user.GetDesignateUsersReq, user.GetDesignateUsersResp]("/user/get_users_info")
AddFriend = newApi[relation.ApplyToAddFriendReq, relation.ApplyToAddFriendResp]("/friend/add_friend")
```

#### 3. **Blocking or Async?** → **Blocking (Synchronous)**

**Location:** `pkg/api/fn.go:30-44`

The API calls are **blocking/synchronous** by default:

```go
func (a *Api[Req, Resp]) Invoke(ctx context.Context, req *Req) (*Resp, error) {
    resp := new(Resp)
    if err := network.ApiPost(ctx, a.api, req, resp); err != nil {
        return nil, err
    }
    return resp, nil
}
```

This is similar to **Java's BlockingStub** - it blocks until the response is received.

### Architecture Comparison:

| Java gRPC | This Go SDK |
|-----------|-------------|
| `ManagedChannel` | `http.Client` (pkg/network/http_client.go:15) |
| `xxxBlockingStub` | `Api[Req, Resp].Invoke()` (pkg/api/fn.go:30) |
| `xxxAsyncStub` | `Api[Req, Resp]` + goroutines (manual) |
| gRPC transport | HTTP/1.1 POST + JSON |
| Server streaming | **WebSocket** (internal/interaction/long_conn_mgr.go) |

### Why WebSocket Instead of gRPC Streaming?

For **push messages** and **real-time events**, this SDK uses **WebSocket** with a 3-goroutine pump pattern:

**Location:** `internal/interaction/long_conn_mgr.go:147-367`
- `readPump()` - receives pushed messages
- `writePump()` - sends requests
- `heartbeat()` - ping/pong keepalive

This replaces gRPC's bidirectional streaming.

### Example Usage:

**Location:** `internal/user/server_api.go:19-22`

```go
func (u *User) getUsersInfo(ctx context.Context, userIDs []string) ([]*sdkws.UserInfo, error) {
    req := &user.GetDesignateUsersReq{UserIDs: userIDs}
    return api.ExtractField(ctx, api.GetUsersInfo.Invoke, req, (*user.GetDesignateUsersResp).GetUsersInfo)
}
```

This is equivalent to Java's:
```java
GetDesignateUsersResp resp = blockingStub.getDesignateUsers(req);
return resp.getUsersInfoList();
```

### Key Takeaways:

1. **No gRPC channels or stubs** - The SDK uses standard HTTP with a blocking call pattern
2. **HTTP Client acts as the channel** - Single global `http.Client` instance
3. **API type system acts as stubs** - Generic `Api[Req, Resp]` pattern with typed endpoints
4. **Blocking calls by default** - Similar to Java's BlockingStub
5. **WebSocket for push messages** - Replaces gRPC streaming for real-time communication
6. **Protocol Buffers for serialization only** - Not used for gRPC RPC framework
